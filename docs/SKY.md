# 리온의 하늘전투 — 설계

두 번째 게임. 텐가이(天外魔境 아님 — Psikyo 『戦国ブレード / Tengai』, 1996)를
기반으로 한 횡스크롤 슈팅.

## 원작에서 가져온 것

조사한 원작 사양과 이식 결과다. 원작을 흉내내되 대상이 아이라 몇 가지를 늦췄다.

| 텐가이 | 여기 | 왜 |
|---|---|---|
| 횡스크롤, 탈것이 아니라 **사람이 난다** | 리온이 직접 난다 | 얼굴 스프라이트를 그대로 쓸 수 있다 |
| A탭 = 샷, A홀드 = 차지, B = 봄 (2버튼) | 샷 자동, **궁극기 버튼 1개** | 요청. 아이가 두 버튼을 동시에 못 누른다 |
| 파워업 4개 모으면 최대 | 파워 4단계 | 그대로 |
| 파워업하면 사역마(옵션)가 늘어난다 | 파워 2부터 옵션 2기 | 그대로 |
| 봄 최대 6, 화면 탄 소거 + 광역 피해 | 궁극기 최대 6, 같은 효과 | 그대로 |
| **적과 부딪히면 파워 1단계만 잃는다** | 그대로 | 원작이 이미 관대하다. 아이에게 딱 맞다 |
| **적탄에 맞으면 즉사** | 그대로 (연습 모드는 목숨 무한) | 긴장은 남기되 벌은 없앤다 |
| 코인은 늦게 먹을수록 값이 떨어진다 (2000→200) | 그대로 | 앞으로 나가게 만드는 장치 |
| 봄이 꽉 찼을 때 봄을 먹으면 10000점 | 그대로 | 그대로 |
| 7스테이지, 앞 3개는 4개 중 무작위 | **10탄 고정 순서** | 요청. 아이가 "몇 탄까지 깼다"를 세야 한다 |
| 보스가 변신한다 | 페이즈마다 형태·패턴·색이 바뀐다 | 그대로 |
| 빠른 **조준탄**(Psikyo 특유) | `aimed` 를 모든 적의 기본 패턴으로 | 그대로 |
| 2주차는 탄이 빽빽해진다 | 없음 | YAGNI |
| 스테이지 5 이후 루트 분기 | 없음 | 10탄 일렬이 진행도 표시에 맞다 |

원작의 차지샷은 뺐다. 버튼이 하나뿐이고, 자동 발사와 궁극기만으로도
아이가 조작할 수 있는 상한에 가깝다.

## 화면과 조작

- 논리 해상도 416×192. 기존 게임과 같은 캔버스·정수 배율·가로 모드 강제를 그대로 쓴다.
- **이동**: 화면 아무 데나 끌면 리온이 따라온다. 손가락이 놓인 지점이 아니라
  **집은 순간부터의 이동량**을 더한다(상대 드래그). 손가락이 캐릭터를 가리지 않는다.
- **발사**: 자동.
- **궁극기**: 우하단 버튼. 기존 게임의 발사 버튼과 같은 자리·같은 크기다.
- 키보드: 방향키/WASD 이동, Space·X 궁극기 (개발·데스크톱용).

## 판정

- 플레이어 피탄 판정은 **4×4** 다. 그림(14×22)보다 훨씬 작다 — 슈팅의 관례이고,
  이게 없으면 탄막을 피할 수 없다.
- 적 판정은 그림 크기 그대로.
- 궁극기 발동 중과 부활 직후에는 무적이다.

## 탄 패턴

`GunSpec.pattern` 하나가 곧 패턴이다. 적·보스가 같은 DSL을 쓴다.

| 패턴 | 내용 |
|---|---|
| `aimed` | 플레이어를 정조준한 빠른 탄. Psikyo 기본기 |
| `spread` | 조준 방향 기준 부채꼴 n갈래 |
| `ring` | 전방위 n갈래 |
| `spiral` | 한 발씩 각도를 돌려가며 계속 |
| `homing` | **유도탄**. 초당 turn 라디안까지 플레이어 쪽으로 꺾는다 |
| `wave` | 진행 방향에 사인파를 얹은 줄기 |
| `burst` | 날아가다 일정 시간 뒤 링으로 터진다 |
| `rain` | 화면 위쪽에서 쏟아진다 (광역 차단) |
| `arc` | 부채꼴을 시간에 걸쳐 쓸어낸다 |
| `laser` | 예고선을 먼저 그리고 빔을 쏜다 (광역) |

유도탄은 수명이 있고, 수명이 끝나면 유도를 멈추고 직진한다. 무한히 쫓아오면
피할 방법이 없어서다.

## 구조

순수 계층 `src/sky/` (DOM 금지, eslint 로 강제):

| 파일 | 책임 |
|---|---|
| `types.ts` | 상태 타입 전부 |
| `tuning.ts` | 상수 |
| `rng.ts` | 결정적 LCG — 리플레이 테스트가 성립하려면 `Math.random()` 을 못 쓴다 |
| `bullets.ts` | 패턴 생성 + 탄 이동 |
| `enemies.ts` | 적 원형(이동 경로 · 총) |
| `boss.ts` | 보스 페이즈·파츠 |
| `player.ts` | 이동 · 샷 · 옵션 · 궁극기 |
| `stages.ts` | 10탄 타임라인 |
| `update.ts` | 한 프레임 |
| `scenes.ts` | 씬 전이 · 기록 |

껍데기: `src/render/sky.ts`(그리기), `src/ui/skyControls.ts`(버튼),
`src/ui/skySelect.ts`(탄 고르기), `src/skyApp.ts`(둘을 잇는 접착부).

`main.ts` 는 `route` 하나로 갈라진다. **기존 게임 코드는 건드리지 않는다** —
분기 조건만 추가한다.

## 보스를 그림이 아니라 코드로 그리는 이유

10탄이면 보스가 10마리다. 40×34 도트를 20프레임 손으로 찍는 대신
`BossShape` 파라미터(몸통 모양 · 색 · 파츠 위치)를 렌더러가 해석해 그린다.
페이즈마다 형태가 바뀌는 원작의 변신을 표현하기에도 이쪽이 맞다.
잡몹은 작아서 도트가 더 잘 읽히므로 도트로 찍는다.

## 지형

없다. 배경은 순수하게 장식이고 충돌하지 않는다. 원작에는 지형 충돌이 있지만,
탄을 피하다 벽에 갈려 죽는 건 아이에게 설명하기 어려운 죽음이다.

## 보스 체력은 계산이 아니라 측정으로 정했다

처음에는 "초당 피해 × 원하는 초"로 계산해서 체력을 적었다. 전부 틀렸다.
실제 초당 피해는 확산각·보스 이동·히트박스에 달려 있어서 계산으로 안 나온다.
3갈래를 0.22rad 로 벌렸더니 280px 떨어진 보스에서는 바깥 두 갈래가 ±60px
빗나가, 이론값 207 이던 초당 피해가 실측 43 이었다.

그래서 `tools/sky_balance.mts` 를 만들었다. 완벽하게 조준하는 가짜 플레이어로
한 번 돌려 실측 dps 를 구하고, 목표 시간(1탄 14초 → 10탄 30초)에 맞춰
`stages.ts` 의 체력 숫자를 다시 쓴다.

```
npx vite-node tools/sky_balance.mts          # 재 보기만
npx vite-node tools/sky_balance.mts --write  # stages.ts 에 반영
```

탄 밸런스를 건드렸으면 이걸 다시 돌려야 한다.

**보스 체력의 단조 증가를 규칙으로 강제하지 않는다.** 제자리에서 도는 보스는
잘 맞아서 체력이 더 필요하고, 화면을 쓸고 다니는 보스는 적은 체력으로도
오래 간다. 지켜야 할 건 싸우는 *시간* 이지 체력 숫자가 아니다.
`schema.ts` 는 자릿수 오타만 잡는다.

## 눈으로 확인하기

브라우저 없이 화면을 그려 본다. `@napi-rs/canvas` 는 **개발 의존성으로 남기지
않는다** — 그림 확인에만 쓰므로 필요할 때만 깐다.

```
npm install --no-save @napi-rs/canvas
npx vite-node tools/sky_preview.mts   # tools/.build/sky_*.png
```

봇 생존 조사도 같이 찍힌다 (1탄 0회 → 10탄 7~8회 죽음).

## 그리다 두 번 틀린 것

기록해 둔다. 다음에 또 같은 실수를 한다.

1. **아군 탄과 적탄을 둘 다 노란 원으로 그렸다.** 화면에서 구분이 안 됐다.
   아군은 청록 대시, 적은 어두운 테두리를 두른 색 구슬로 갈랐다.
2. **궁극기 번개를 `lighter` 로 그렸다.** 얼음 골짜기처럼 흰 배경에서는
   통째로 사라졌다. 대모험의 100만볼트에서 이미 겪은 실수인데 반복했다.
   가산 합성을 쓰지 않고 파란 글로우 → 밝은 파랑 → 흰 심을 그대로 겹친다.
   선은 얇게, 진폭은 길이에 비례해서 크게, 꺾임은 위아래 번갈아.
3. **잡몹 체력을 너무 낮게 잡았다** (새 3, 벌 4). 화면에 들어오는 순간
   녹아서 아무것도 안 보였다. 게다가 아군 탄이 화면 오른쪽 밖까지 날아가
   등장 전에 죽였다. 체력을 올리고 탄을 화면 끝에서 끊었다.
4. **적이 등장하자마자 죽어 한 발도 못 쐈다.** 첫 발사 지연을 발사 간격과
   같게 뒀기 때문이다. 늦어도 0.7초 안에 한 발은 나가게 했다.
5. **도트를 전부 오른쪽 보게 찍어 놓고 왼쪽으로 날렸다.** 렌더러에서 뒤집는다.
