# 스테이지 구성 (전 10탄)

레벨 데이터는 손으로 쓰지 않는다. `tools/make_levels.py` 가 재사용 구간 블록을
조립해 `src/levels/stage-01.json` ~ `stage-10.json` 을 만든다. 고칠 때는 그 파일을
고치고 `python3 tools/make_levels.py` 를 다시 돌린다.

## 진행

- 1탄은 항상 열려 있고, 이전 탄을 깨면 다음 탄이 열린다 (`src/game/unlock.ts`)
- 진행도는 모드별로 따로 저장된다 (`leon_game.progress.practice` / `.challenge`)
- 연습 모드는 체크포인트 부활·목숨 무한, 도전 모드는 처음부터·목숨 3·400초

## 레벨이 지켜야 하는 규칙

`src/levels/schema.ts` 의 `validateLevel()` 이 검사하고, 부팅 시 10탄 전부에
`assertValidLevel()` 을 걸어 잘못된 레벨로는 시작하지 못하게 한다.

| 규칙 | 내용 |
|---|---|
| 1 | 모든 행 길이 = width, 행 수 = height |
| 2 | 미정의 타일 문자 없음 |
| 3 | spawn 이 빈칸이고 바로 아래가 땅 |
| 4 | 이동발판이 걸치지 않은 구덩이 폭 ≤ 달리기 도달 거리(7타일) |
| 5 | 통과 통로 높이 ≥ 2타일 |
| 6 | 모든 체크포인트가 설 수 있는 자리 |
| 7 | goal 이 레벨 범위 안 |
| 8 | 용암이 지면 두 줄을 모두 채운다 (한 줄이면 위를 걸어 지난다) |
| 9 | 가시 아래가 땅 (공중에 뜬 가시는 보이지 않는 함정) |
| 10 | 오를 수 없는 단차 없음 — 점프 최고 높이 4타일 초과 금지 |

**규칙 10 이 실제로 버그를 잡았다.** 처음에 2·3탄에 높이 5타일 파이프를 두었는데,
최고 점프는 73px(4.57타일)이고 5타일은 80px 이라 물리적으로 넘을 수 없었다.

## 통과 가능성 검증

두 층으로 나눈다.

- **지형 도달성** (`tests/helpers/reach.ts`) — 적을 완전히 무시하고, 서 있을 수
  있는 구간들을 그래프로 만들어 스폰에서 골까지 BFS로 닿는지 본다. 10탄 전부
  검사한다. 레벨 작성자가 실제로 저지르는 잘못(넘을 수 없는 구덩이, 고립된 발판,
  오를 수 없는 단차)이 여기 걸린다.
- **실제 플레이** (`tests/helpers/bot.ts`) — 1탄만. 입력→물리→규칙→씬이 맞물려
  도는지 확인하는 통합 테스트다. 적 전투 실력이 필요한 뒷 탄까지 봇에게
  요구하지는 않는다 — 봇이 못 깨는 것과 레벨이 잘못된 것은 다른 문제다.

## 좌표를 손으로 쓰지 않는 이유

처음에는 적·발판·체크포인트를 절대 좌표로 적었다. 구간 폭을 하나 바꾸면 뒤의
모든 좌표가 밀려서 체크포인트가 계단 위에 놓이고 발판이 구덩이를 빗나갔다.
지금은

- 적·발판은 **구간 안의 상대 좌표**로 적고 조립할 때 오프셋을 더한다
- 체크포인트는 완성된 격자에서 **설 수 있는 열을 찾아 자동으로** 뽑는다
- MAX_PIT(6타일)를 넘는 구덩이·용암에는 **고정 발판을 자동으로** 깐다

세 가지가 좌표 어긋남을 원천 차단한다.
